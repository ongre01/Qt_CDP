# 사용자 가이드

## 준비 사항

- Chrome 또는 Chrome 호환 브라우저의 실행 파일 경로
- 다른 Chrome 인스턴스와 분리해서 사용할 **CDP 전용 사용자 데이터 디렉터리**
- 로컬 CDP 주소. 기본값은 `http://127.0.0.1:9222`이며, 주소를 생략하면 HTTP로 해석하고 포트가 없으면 `9222`를 사용합니다.
- 자동 로그인 기능을 사용할 경우 코레일 회원번호와 비밀번호

앱은 CDP 주소의 호스트가 `127.0.0.1`, `localhost`, `::1` 가운데 하나가 아니면 Chrome 시작, 자동 로그인, 열차 정보 수집을 실행하지 않습니다.

## 실행과 Chrome 연결

1. **Chrome 실행 파일**에 브라우저 실행 파일을 지정합니다. 기본값은 `C:/Program Files/Google/Chrome/Application/chrome.exe`입니다.
2. **CDP 사용자 데이터**에 전용 디렉터리를 지정합니다. 기본값은 `C:/Temp/ChromeCDP`입니다.
3. **CDP용 Chrome 시작**을 누릅니다.

앱은 지정한 브라우저를 `--remote-debugging-port=<포트>` 및 `--user-data-dir=<디렉터리>` 인수로 별도 실행하고, `/json/version` 엔드포인트가 준비될 때까지 확인합니다. 준비 후에는 열차 정보 수집을 시작합니다.

브라우저를 직접 CDP 모드로 실행한 경우에는, 그 주소를 **CDP 주소**에 입력해 사용할 수 있습니다. 이 경우에도 기능은 로컬 주소만 지원합니다.

## 코레일 자동 로그인

1. **회원번호**와 **비밀번호**를 입력합니다.
2. **코레일 자동 로그인**을 누릅니다.
3. 앱이 CDP로 새 탭을 열어 코레일 로그인 화면을 탐색하고, 회원번호·비밀번호 입력 및 로그인 버튼 클릭을 시도합니다.
4. 완료 또는 오류는 창 하단 상태 메시지로 확인합니다. 로그인 후의 상태는 브라우저에서 다시 확인하세요.

### 로그인 정보 저장에 관한 중요 사항

현재 구현은 로그인 버튼을 누를 때 회원번호와 비밀번호를 `QSettings`의 사용자 범위 INI 저장소의 `Qt_CDP/Qt_CDP`, `KorailLogin` 그룹에 저장하고 다음 실행 때 다시 채웁니다. 화면 상단의 “로그인 정보를 저장하지 않습니다”라는 설명과 다를 수 있으므로, 공유 PC에서는 사용하지 말고 필요하면 해당 사용자 설정 파일을 삭제하세요.

## 열차 정보 확인과 병렬 매크로

열차 정보 수집이 활성화된 뒤 Chrome에서 코레일 열차 조회 페이지를 열면, 앱이 페이지별 탭을 만들고 다음 열을 표시합니다.

| 열 | 내용 |
| --- | --- |
| 선택 | 매크로 대상 열차 선택 |
| 열차 / 번호 | 열차 종류와 열차 번호 |
| 출발역 / 출발 시각 | 출발 정보 |
| 도착역 / 도착 시각 | 도착 정보 |
| 소요 시간 | 운행 시간 |
| 일반실 / 특실 | 파싱한 좌석 상태 |

1. 각 열차 조회 탭에서 확인할 열차의 **선택** 칸을 체크합니다.
2. **병렬 매크로 시작**을 누릅니다.
3. 각 탭의 컨트롤러가 선택 열차를 확인합니다. 예약 가능한 좌석이 없으면 해당 조회 페이지를 새로고침해 다시 확인합니다.
4. 예약 가능 좌석을 찾으면 기본 동작은 매크로를 멈추고 상태 메시지로 알립니다.
5. **가능 시 자동 예매**를 선택하면, 예약 가능한 좌석 발견 시 해당 탭에서 예매 버튼 선택과 이어지는 확인 절차를 자동으로 시도합니다.
6. **무변화 알림** 시간을 설정하면, 실행 중인 열차 조회 탭에서 그 시간 동안 DOM 변화가 없을 때 ntfy 알림을 한 번 보냅니다. 기본값은 60초이며, 화면 변화가 다시 감지되면 다음 무변화 구간을 새로 감시합니다.
7. 중단하려면 **병렬 매크로 중지**를 누릅니다.

여러 조회 탭을 열면 탭별로 병렬 처리가 가능합니다. 탭을 닫거나 CDP 연결이 끊어지면 그 탭의 정보와 매크로 상태가 정리됩니다.

> 주의: 자동 예매는 실제 서비스 화면의 구조와 응답에 의존합니다. 성공 메시지가 표시되어도 예약·결제 상태를 코레일 사이트에서 반드시 확인하세요.

### 예매 완료 알림

예매 성공 처리 시 앱은 현재 고정된 `https://ntfy.sh/ktx` 엔드포인트에 “KTX 예매 완료” 알림을 보냅니다. 코드에는 이 요청을 위한 사용자별 토큰이나 주제 설정이 없습니다. 이 채널과 메시지를 민감한 통신 수단으로 취급하지 말고, 개인정보·예약 세부 정보를 추가로 입력하지 마세요.

병렬 매크로가 실행 중이고 열차 조회 탭이 하나 이상 있을 때, 설정한 시간 동안 DOM 스냅샷 내용이 바뀌지 않으면 같은 엔드포인트에 “KTX 매크로 화면 변화 없음” 알림을 보냅니다. 같은 무변화 구간에는 중복 알림을 보내지 않으며, 새 화면 변화가 확인되면 감시 타이머가 다시 시작됩니다.

## 방문 페이지 스냅샷

1. **저장 폴더**를 확인하거나 변경합니다. 기본 경로는 앱 데이터 위치 아래의 `page-captures`입니다.
2. **방문 페이지 기록 시작**을 누릅니다.
3. CDP로 연결된 Chrome에서 페이지를 탐색합니다. 앱은 대상 페이지의 DOM 스냅샷을 수집해 지정한 폴더에 저장합니다.
4. 중지하려면 버튼을 다시 누릅니다. **저장 폴더 열기**로 결과를 탐색할 수 있습니다.

스냅샷은 `DOMSnapshot.captureSnapshot`을 사용합니다. 저장 과정에서 입력 요소 값, textarea 값, 그리고 input의 `value` 속성 값은 `[REDACTED]`로 치환됩니다. 그러나 페이지의 다른 텍스트, URL, 제목 등은 저장될 수 있으므로 저장 폴더의 접근 권한을 관리하세요.

저장 폴더에는 다음 항목이 생성됩니다.

```text
<저장 폴더>/
  manifest.jsonl
  <capture-id>/
    dom-snapshot.json
```

- `manifest.jsonl`: 한 줄에 하나씩 저장한 캡처 메타데이터(JSON)
- `dom-snapshot.json`: `schemaVersion`, `captureId`, `capturedAt`, 그리고 정제된 `domSnapshot`을 포함한 JSON

Chrome·DevTools·Edge 내부 페이지는 저장 대상에서 제외됩니다.

## 문제 해결

| 증상 | 확인할 사항 |
| --- | --- |
| Chrome을 시작할 수 없음 | 실행 파일 경로가 존재하는지, CDP 주소가 로컬 호스트인지, CDP 사용자 데이터 디렉터리가 비어 있지 않은지 확인합니다. |
| CDP 연결 또는 수집이 시작되지 않음 | 주소가 유효한 HTTP(S) URL인지와 포트가 Chrome의 원격 디버깅 포트와 일치하는지 확인합니다. 기본 포트는 `9222`입니다. |
| 열차 목록이 보이지 않음 | 열차 정보 수집이 활성화된 상태에서 Chrome의 실제 코레일 열차 조회 페이지를 열었는지 확인합니다. |
| 매크로가 바로 멈춤 | 선택된 열차가 있는지, 선택 열차의 번호·출발·도착 시각이 표시되는지, CDP 연결과 해당 탭이 유지되는지 확인합니다. |
| 스냅샷을 저장할 수 없음 | 저장 폴더를 생성·쓰기할 권한이 있는지 확인합니다. |

상태 표시줄의 오류 메시지는 현재 실행 단계의 가장 직접적인 원인을 알려줍니다.
